# 独立审查

1. 从 `inbox` 获取被派候选，`inspect` 固定任务 ID、候选哈希、适用规格、原验收和开发证据。按项目标准查看实际差异。
2. 在一次审查中检查需求覆盖、实现及输入输出一致性、直接系统影响。使用 `checkEvidence` 读取实际程序回执，核对测试断言和最终候选。围绕具体疑点找反例。对未验证的部分说明原因。
3. 对每个发现记录复现条件、影响、位置、证据与建议。违反本票验收、必要检查失败或实际越界属于阻塞；无关历史问题单独记录。
4. 以原候选哈希及三维证据调用 `review`。通过时按 `guide` 为每一维填写 `checkIds`；交付清单中的既有测试变更须在 `testReview` 说明断言、覆盖及反例核对结果。有阻塞用 `changes`，按原因区分契约漂移、证据缺口和可复现的质量反例。确认 `stored` 后结束，审查只读。
