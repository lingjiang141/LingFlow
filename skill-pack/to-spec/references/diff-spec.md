# 差异规格模板

只在已有适用有效规格且本轮目标发生变化时读取。一个已确认的变化可以很短；字段已有真实出处时引用即可，不为格式重复需求或重新索要已存在的批准。

~~~markdown
# 本轮差异：<范围／迭代标识>

基线：原规格的真实路径或 URL、版本／相关章节。
仍有效的前序差异：引用；无则 None。
状态与批准依据：真实已批准来源，或明确待批准／待决。

## 本轮行为变化

| 差异 ID | 原需求／新增需求 | 原已批准行为 | 本轮目标行为 | 增量验收条件与证据边界 |
| --- | --- | --- | --- | --- |
| CHG-001 | 原需求 ID 或新增 ID | 与实际代码现状分别说明 | 明确新增／修改／删除的行为 | 可观察结果及如何确认 |

## 保留规则与范围

本轮相关且继续成立的权限、数据隔离、兼容及业务约束；用精确引用，不复制全部原规格。列明本轮排除范围。

## 直接影响

受影响的能力、公共约束、既有 AC、必要迁移及回归边界。活动票／责任只列真实已知项，未知影响待派发前核定，不虚构文件或成员授权。

## 关联修复与待决项

恢复原行为的问题引用原 AC 和已有修复记录；与新增规则分开。没有相关项时省略该段，关键未决项保持可见。

## 后续承接

票与预定路线引用本差异及原规格，只覆盖本轮增量和直接影响。明确仍需决定的事项；采用后在安全边界合回有效规格并保留基线和历史。
~~~

差异 ID 保持本轮唯一，原需求 ID 保留。新增需求给新 ID，变更用“原需求引用 + 差异 ID + 本轮 AC”追踪，保留已验收历史。不要将未批准建议写成有效目标，也不要把文档发布写成已实现或已验收。
